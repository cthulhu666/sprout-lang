# Benchmark snapshot — 2026-07-11 (pre-Phase-D baseline)

Warm-sampled execution-only baseline on current `master` (`fe56a46`), captured **before** any
Phase D (numeric fast-path) work lands, so the general impact of Phase D — especially the
generalized B1 inline-`Vector T` access — can be measured against a fixed reference. Same M1-class
host and `just compile-native` (typed codegen, `clang -O2`) as the 2026-06-30 snapshot.

Tiny benchmarks are load-sensitive: samples were taken back-to-back warm, discarding the first run
and any clearly loaded outlier (the 2026-06-30 file documents the same caveat). Ranges are reported
alongside the representative figure.

## A* (100×100 grid, 100 runs, path = 198)

| | Per run (µs) | Samples (warm) |
|---|---|---|
| **Sprout — pre-Phase-D (2026-07-11)** | **~305** | 300, 304, 308, 308, 314, 322 (loaded outliers ~332–339 discarded) |
| Sprout — root-once (2026-06-30) | ~300 | 297, 299, 301, 310 |

**Read:** flat across the whole recent arc — no change. A* is integer-only and its hot relax/expand
loop is dominated by `MutVec Int` access (`mutvec_get`/`mutvec_set`).

## N-Queens (N=12, count = 14200)

| | Time (ms) | Samples (warm) |
|---|---|---|
| **Sprout — pre-Phase-D (2026-07-11)** | **~505** | 494, 502, 507, 540 (loaded outliers ~604–652 discarded) |
| Sprout — root-once (2026-06-30) | ~797 | 763, 766, 797, 822 |

**Read:** **~1.5× faster** than 2026-06-30 — a real gain (even the loaded outliers sit well under
the old tight 763–822 band). This came from the ~11 days of intervening CPR/codegen work, **not**
from the 2026-07-11 `mutmatrix_row_add_scaled_into` kernel: nqueens uses immutable `Vec Bool` and
does not touch that path. Its dominant cost is `vec_set` returning a fresh `Vec` per placement
(persistent-vector copy for free backtracking), which Phase D does **not** target.

## Relevance to Phase D (what to watch)

- **A* is the key non-numeric witness for generalized B1.** Zero floats; it exercises
  `Vector Int` element access in a tight loop. Under the original Double-scoped B1 it would gain
  *nothing*; under generalized B1 it should speed up — **provided B1 covers the `mutvec_get`
  (`Maybe`-returning `vector_get`) path**, not just `vector_get_direct`. If B1 only inlines the
  direct path, A* first needs the same direct-access-idiom rewrite the recognizer got. This
  requirement is recorded in `docs/phase-d-numeric-fastpath-design-2026-07-11.md` §4/§9.
- **N-Queens is expected to gain little from Phase D.** B1 would inline its `Vec Bool` reads, but
  its cost is the persistent-vector copy in `vec_set`, out of Phase D scope. Re-measure to confirm
  it does not *regress* rather than to expect a win.
