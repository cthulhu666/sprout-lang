# Benchmark snapshot — 2026-07-11 (Phase D B2 landed)

Same M1-class host, same `just compile-native` (typed codegen, `clang -O2`) and warm-sampling
methodology as `bench/results-2026-07-11.md` (the pre-Phase-D baseline). This snapshot measures the
impact of **Phase D B2 — leaf-loop GC-root elision** (`op_triggers_gc` now treats a verified
allow-list of non-allocating read/store externs — `vector_get_direct`/`vector_mutset`/`vector_length`
— as non-triggers). A/B captured on the same machine in the same session: pre-B2 built from the
committed seed, B2 from the refreshed seed.

Tiny benchmarks are load-sensitive: samples taken back-to-back warm, first run discarded, clearly
loaded outliers dropped.

## Digit recognizer (64→24→10 MLP, 25 epochs SGD over 500 samples) — the B2 witness

| | Wall (s) | Samples (warm) | Accuracy |
|---|---|---|---|
| **Sprout — B2 (2026-07-11)** | **~1.67** | 1.68, 1.66, 1.67 (first 1.86 discarded) | 92.6667% (139/150) |
| Sprout — pre-B2 (2026-07-11) | ~3.03 | 3.05, 3.03, 3.03 (first 3.18 discarded) | 92.6667% (139/150) |

**Read: ~1.8× faster, bit-identical accuracy.** The dot kernel's inner loop carried 3
`push_i64_root`/`pop_roots` calls per element around the two non-allocating `vector_get_direct`
reads (the largest profile category, per `docs/digit-recognizer-performance-plan-2026-07-10.md`).
B2 removes them: the kernel reads `Vector Double` through a bare `IRCall vector_get_direct` on a
source-concrete type, exactly the site B2 reaches.

## A* (100×100 grid, 100 runs, path = 198) — no-regression check

| | Per run (µs) | Samples (warm) |
|---|---|---|
| **Sprout — B2 (2026-07-11)** | **~305** | 286, 308, 320, 315 |
| Sprout — pre-Phase-D (2026-07-11) | ~305 | 300, 304, 308, 308, 314, 322 |

**Read: flat, no regression.** A* got no *win* — but not because its wrapper allocates. CPR unboxing
already sees through `mutvec_get` and emits the non-allocating `vector_get_unboxed` (verified:
`astar.sprout --emit-ir` has 4). A* got nothing because this commit reclassifies only plain
`IRCall`, not the `IRCallUnboxed2` op that unboxing produces — `op_triggers_gc` still has blanket
`IRCallUnboxed2 -> true`. Extending the allow-list to non-allocating `IRCallUnboxed2` variants
(per-name verified; excluding `regex_find_range`/`term_read_line`/`env_get`_unboxed) is the follow-up
that reaches idiomatic MutVec/Map reads.

## N-Queens (N=12, count = 14200) — no-regression check

| | Time (ms) | Samples (warm) |
|---|---|---|
| **Sprout — B2 (2026-07-11)** | **~500** | 497.9, 511.6, 481.9, 500.6 |
| Sprout — pre-Phase-D (2026-07-11) | ~505 | 494, 502, 507, 540 |

**Read: flat, no regression.** N-Queens' cost is `vec_set` returning a fresh persistent `Vec` per
placement (copy for free backtracking) — outside B2's scope.
