# Benchmark snapshot — 2026-07-26 (devirtualization + tuple-CPR: effect on astar/nqueens/digit)

Checks whether the 2026-07-25 codegen work moved the three headline benchmarks. Those commits are
the only codegen-affecting changes in the window: concrete-instance **devirtualization**
(`d4cd9e2`, `613d8b8`, `0565fd6` — drop the runtime typeclass dictionary for statically-known
instances, `docs/devirtualization-v0.md`) and **tuple CPR / scalar replacement**
(`ceff7b4`, `29f602b`, `docs/scalar-replacement-v0.md`). The other two compiler-source commits in
the 3-day window (records-v0, derived `Enum`) are feature work these examples' code paths don't touch.

**Method.** Byte-identical A/B: baseline seed = `ad8dc8e` (parent of the first optimization commit),
HEAD = `0565fd6`. The example sources, runtime, and prelude are **identical** across the window
(`git diff` empty), so the only variable is the compiler. Evidence is anchored on the deterministic IR
delta — allocation call sites (`sprout_alloc_closure_env` / `sprout_alloc_tuple_blob`) and dispatch
call sites — with wall-clock (best-of-5, warm, M1-class host) as corroboration only. Both paths go
through `clang -O2`, which does its own SRA/devirt and can mask a Sprout-level IR win in wall-clock.

## astar / nqueens / digit — no measurable improvement

| Benchmark | IR: fns eliminated | IR: heap allocs removed | Wall-clock (best-of-5) |
|---|---|---|---|
| **A\*** (100×100, 100 runs) | 0 — *identical function set* | 0 (21 → 21) | 293 → 290 µs/run (noise) |
| **N-Queens** (N=13) | 0 — *identical function set* | 0 (17 → 17) | 2034 → 2040 ms (noise) |
| **Digit recognizer** (net, 30 epochs) | **7** | **7** (closure-env 33 → 26) | 0.54 → 0.53 s (noise), 139/150 unchanged |

**Why.** In this compiler a typeclass method call materializes its dictionary as a
`sprout_alloc_closure_env` object, so devirtualization shows up as *closure allocations disappearing*,
not as an LLVM indirect call (there were zero of those at either revision).

- **astar / nqueens** produce a byte-identical function set pre/post (`comm` on the `define` names is
  empty; the ~550 differing IR lines are pure SSA-register renumbering). Their inner loops — grid
  arrays, a comparison-based open set, backtracking — never route through the concrete-instance
  dispatch these passes target, so there is nothing to devirtualize and tuple CPR does not fire
  (tuple-blob count unchanged).
- **digit** genuinely sheds 7 functions — every `__sprout_ir_eta___tc_ToString_Int/Double_to_string`
  eta-wrapper plus 2 folded lambdas — i.e. the devirt + eta-flatten passes firing on the
  **accuracy-reporting `to_string` path**. But that path runs a handful of times; the training hot
  loop (`range_fold`/`range_each` over the layers) does raw Int/Double arithmetic with no typeclass
  dispatch and is untouched. So the IR shrinks but wall-clock is flat — the eliminated allocations
  were cold, and `clang -O2` had already neutralized any residual cost.

**Net: no regression, no improvement on these three.** The wins these passes deliver land in
dispatch-heavy code, which none of the three exercises in a hot loop.

## New witness — `bench/dispatch/` — isolates the devirt payoff

To show the optimization where it *does* pay, `bench/dispatch/dispatch_bench.sprout` puts a concrete
class-method call in a tight loop: `weight(coin_of(i))` summed over 20M iterations, at instance
`Weight Coin` (no superclass, no context — the maximal "dict → 0" shape). `coin_of` is a pure `match`
(no allocation), so the dispatch dictionary is the loop body's **only** per-iteration heap traffic —
the same isolation `bench/unboxed_read/` gives root-elision.

**Per-iteration fold body (`__sprout_ir_lambda_12`), IR:**

| | Baseline | HEAD |
|---|---|---|
| `sprout_alloc_closure_env` (dispatch dict) | **1** | **0** |
| dispatch call | `__cm_Weight_weight` generic wrapper (indirect) | direct `__tc_…Coin_weight` |

**Wall-clock (best-of-5, 20M calls):**

| | Baseline | Devirt (HEAD) | |
|---|---|---|---|
| **dispatch witness** | ~732 ms | **~507 ms** | **~1.44×** |

Checksum `206666480` identical on both — the optimization is value-neutral, as designed. The ~225 ms
saved over 20M iterations (~11 ns/call) is one dispatch-dict allocation + its GC amortization + the
`__cm_` wrapper indirection, removed. This is the win the three headline benchmarks dilute (astar) or
keep in cold code (digit); a dispatch-bound loop surfaces it directly.

## Correctness

All six binaries produce identical output to their pre-change builds (astar path=198; N-Queens counts
1/2/92/724/14200/73712; digit 139/150; dispatch checksum 206666480). No source, semantics, or
diagnostic change — devirt and tuple CPR are value-neutral lowering optimizations.
