# Benchmark snapshot — 2026-06-30 (after root-once rooting, PR #108)

Re-run of the 2026-06-29 baseline after landing root-once stack coalescing
(`ir_rooting.sprout`). Same M1-class host, `just compile-native` (typed codegen,
now embedding the new rooting via refreshed seed), execution-only self-timed
`clang -O2` binaries.

**Purpose:** confirm the over-rooting fix — a *compile-time* memory win — does not
regress runtime. It does not.

## Verdict

Root-once rooting is **runtime-neutral** on both benchmarks — no regression, no
clear improvement. Expected: these hot loops have short-lived per-iteration roots
spanning few triggers, so per-trigger re-rooting was never their bottleneck.
Root-once targets values live across *many* triggers (the buffered list literal:
N values × N triggers), which is a **compile-time** cost — there the fix is a 73×
peak-RSS reduction (2943 MB → 40 MB at N=120; see PR #108 / the design doc). The
candidate concern that deferred pops (deeper average shadow-stack) might slow
GC-heavy loops did **not** materialize here.
