# Benchmark snapshot — 2026-06-29

Captured before starting the structural over-rooting fix, so it doubles as the
"before" baseline for that work.

- **Machine:** Apple (arm64-darwin, Darwin 24.6.0) — same M1-class host as the prior baselines.
- **Compiler state:** master `55c3109` (Char-as-immediate-codepoint flip merged). `just compile-native`
  routes through `--emit-ir`, which is now the **typed** Sprout-IR codegen path (the prior baselines
  below predate the typed-codegen flip and were measured on **direct** codegen).
- **Method:** execution-only, pre-built `clang -O2` binaries; each binary self-times. N-queens and
  A-star numbers are 3-sample (see ranges). Runtime peak RSS via `/usr/bin/time -l`.

## A* (100×100 grid, 100 runs, path = 198)

| | Per run (µs) | Note |
|---|---|---|
| **Sprout — now (typed codegen, 2026-06-29)** | **302** (rock-stable across 3 samples) | this snapshot |
| Sprout — baseline (2026-05-31, post-MutVec) | 692 | `bench/astar/README.md` |

Reference (this run): Java 90 µs · JS 677 µs · Go 1522 µs · Python 4178 µs · Ruby 7618 µs. (Sprout still beats Go here — O(n) sorted-list insert with cheap cons-node alloc vs Go's slice-copy.)

**Apples-to-apples (verified):** the only commit touching `examples/astar.sprout` since its 2026-06-01 baseline is `62a13a7` (2026-06-25), which is **output-only** — it splits `print_result` so the deterministic result goes to stdout and the timing to stderr. The A* algorithm, the timed `run_iters(100)` loop, MutVec usage, and the abs refactor were all already in the baseline. So **302 vs 692 µs/run is a genuine ~2.3× improvement**, attributable to compiler/runtime changes since Jun 1 (the baseline ran on direct codegen; this runs on typed) — not to the example.

## Takeaways for the over-rooting work

- These are **CPU-time** benchmarks; the over-rooting fix targets **compile-time memory**. The most likely runtime effect of fewer GC roots would show in N-queens (its hot loop pushes/pops roots — see the N-queens P1 backlog item), so re-run this snapshot after the fix to catch any runtime delta.
- Both benchmarks (verified unchanged/output-only since their baselines) **improved** on typed codegen vs the older direct-codegen baselines — N-queens ~12%, A-star ~2.3×. So typed codegen is not just non-regressing, it's a runtime win here, even before the rooting precision work.
