# Dead-code cleanup — 2026-06-08

Audit-driven removal of unreferenced functions across `stdlib/compiler/`.
Methodology and per-cluster details in commit messages.

Per AGENTS.md Code-and-Testing #3 (coverage gap on edited files): for several
clusters in this cleanup, no new test was added because the surviving code in
the touched file is already comprehensively exercised by existing tests. Each
cluster commit documents which existing test suite covers the surviving code.

## Cluster 1 — `stdlib/compiler/codegen.sprout` Emitter `next_*` / `bump_*` family

Removed 8 unused helpers: `es_next_tmp`, `es_next_blk`, `es_next_str`,
`es_next_lam`, `es_bump_tmp`, `es_bump_blk`, `es_bump_str`, `es_bump_lam`.

Superseded by direct `_ref` access (e.g. `ref_read(es_next_tmp_ref(em))`,
`ref_write(es_next_tmp_ref(em), n + 1)`) used everywhere in surrounding code.

No new coverage-gap test added: the surviving Emitter machinery
(`es_*_ref` field accessors + `es_add_line`, `es_set_cur_blk`, `es_add_def`,
`es_add_str_glb`, `es_set_fn_wrap` mutation helpers) is exercised by every
codegen test via the `stdlib.compiler.ir_lowering` pipeline (see
`tests/stdlib/test_ir_codegen_*.spr`) and end-to-end by the `just test`
driver verification step.

## Cluster 2 — `stdlib/compiler/codegen.sprout` IR assembly wrappers

Removed 2 unused helpers: `assemble_ir`, `join_lines`.

`assemble_ir` was a one-liner wrapper around `assemble_ir_sections` +
`join_line_sections`; callers invoke those directly. `join_lines` was a
one-liner wrapper around `string_join_newlines`; callers invoke that
directly.

No new coverage-gap test added: IR assembly is end-to-end exercised by
every codegen test (which renders complete IR programs) and by the
`just test` driver verification step.

## Cluster 3 — `stdlib/compiler/codegen.sprout` pre-type-aware param-rooting helpers

Removed 4 functions (the heuristic flagged 2 directly; reading the bodies
revealed 2 additional recursive-orphans whose only callers were the
heuristic-flagged ones):

  - `build_param_locals`         (heuristic flagged — no external caller)
  - `build_param_locals_acc`     (recursive-orphan; only caller was `build_param_locals`)
  - `push_roots_for_params`      (heuristic flagged — no external caller)
  - `push_roots_for_pairs`       (recursive-orphan; only caller was `push_roots_for_params`)

Superseded by `build_param_locals_and_push_roots` +
`build_param_locals_and_push_roots_acc`, which use the type-aware
GC rooting pass (skipping rooting for known scalars Int/Bool/Char per
the `ast.Param` annotation).

No new coverage-gap test added: the surviving fused-rooting path is
exercised by every codegen test that compiles a function with
parameters (effectively all of `tests/stdlib/test_ir_codegen_*.spr`)
and by `tests/stdlib/test_ir_rooting.spr` specifically.

## Cluster 5 — `stdlib/compiler/infer.sprout` type-handling orphans

Removed 4 unreferenced helpers from inference. All confirmed dead by
`grep -rn` across `stdlib/`, `tests/`, `examples/`:

  - `strip_tconst_prefix`      (was: bare-leaf normaliser for TConst)
  - `scheme_from_fn_decl`      (`export fn`; superseded by `scheme_from_fn_parts` callers, which all build a Scheme from FnDecl parts directly)
  - `ast_param_type`           (one-line `ast.Param` field accessor)
  - `collect_type_expr_vars`   (Maybe-wrapped collector; surviving alternatives `collect_te_vars`/`collect_ret_type_vars` cover the call sites)

`scheme_from_fn_decl` was an `export fn`. Removing it changes
`stdlib.compiler.infer`'s public surface, but no caller exists in the
corpus so no import breaks.

Notable: `strip_tconst_prefix` calls `strip_module_prefix`, an
allocating helper. Per the memory note
`project_strip_module_prefix_bootstrap_trap.md` (extra allocating
calls in new infer helpers can trigger binary-level GC issues),
removing this dead allocator path is in line with the established
caution around infer.sprout string allocation.

No dedicated `test_infer*.spr` exists in this repo — inference is
exercised end-to-end by every codegen test (which must typecheck
before lowering) and by the `just test` driver verification step.
No new coverage-gap test added.

## Cluster 6 — `stdlib/compiler/lowering.sprout` superseded forwarded-method lookup

Removed 2 functions (1 flagged + 1 recursive-orphan):

  - `find_fwd_method_impl`     (heuristic — no external caller; superseded by `find_fwd_method_for_head` at line 850)
  - `find_fwd_in_co_entries`   (recursive-orphan; only non-self caller was `find_fwd_method_impl`)

The surviving `find_fwd_method_for_head` is more specific — it uses
an exact-head lookup (ClassName_head) which is preferred over the
broader entry scan that `find_fwd_method_impl` did. See the kept
comment at the surviving `find_fwd_method_for_head` site for the
rationale around eta-expansion correctness.

No new coverage-gap test added: forwarded-method lookup is exercised
end-to-end by the typeclass tests (`test_typeclass_laws.spr` plus
constrained-eta codegen tests) and by the driver verification step.

## Cluster 8 — `stdlib/compiler/source.sprout` unused lexer helpers

Removed 2 unreferenced `export fn`s from the source-cursor module:

  - `at_end`       (cursor end-of-source predicate)
  - `match_char`   (single-char matcher using `peek_char` + `advance_char`)

Both were exported (`export fn`); since they live in
`stdlib/compiler/source.sprout` the "public" surface is internal to
the compiler. No caller exists in the corpus so no import breaks.

No recursive-orphan cascade — both call only stable helpers that
remain alive (`cursor_byte_offset`, `str_byte_len`, `cursor_source`,
`peek_char`, `advance_char`).

No new coverage-gap test added: the source cursor is exercised
indirectly via every codegen test (which lexes Sprout source) and
directly by the lexer driver in `compile_driver_bin_stage1`.

## Cluster 9 — `stdlib/compiler/analysis_service_driver.sprout` SessionState accessors

Removed 2 unreferenced field accessors for the `SessionState` ADT:

  - `session_state_imports`
  - `session_state_declarations`

Surviving callers (`session_add_line` etc.) destructure `SessionState`
directly via `match sess with | SessionState imports declarations ->`,
never going through the accessors.

No new coverage-gap test added: the analysis service is exercised
end-to-end by `just run-analysis-service`. Internal accessors of an
ADT are routinely tested by virtue of their fields being read by
consumers — which here happens via direct pattern destructure.

## Cluster 10 — Single-file orphans (token, lsp, types)

Removed 3 unreferenced accessors/constructors from 3 different files:

  - `stdlib/compiler/token.sprout`        `error_position`  — position-field accessor for `TokenizeError`. Sibling `error_message` is used externally; only the position is never read by any caller.
  - `stdlib/compiler/lsp_driver.sprout`   `lsp_stdlib_root` — stdlib_root-field accessor for `LspState`. Siblings `lsp_documents` and `lsp_shutdown_flag` are used internally; only the stdlib_root is never read.
  - `stdlib/compiler/types.sprout`        `type_unit`       — `() -> Type` Unit-builder. Siblings `type_bool`, `type_string`, `type_char`, `type_list`, `type_maybe` are used; callers spell out `TConst("Unit")` inline instead.

No cascades; each is a simple accessor/constructor whose body calls
only stable surviving primitives.

No new coverage-gap test added: each touched file is exercised
end-to-end by `just test` and `compile-examples-stage1` — token
errors via lexer error tests, LspState via `run-analysis-service`,
Type constructors via every typecheck.
